# 🌐 Internationalization

## 🗣️ Supported languages

The application currently supports:

- Spanish (`es`)
- English (`en`)

## 📁 Translation files

User-facing strings live in:

- `src/assets/i18n/es.json`
- `src/assets/i18n/en.json`

## ⚙️ How language selection works

- available languages are registered during app bootstrap
- the chosen language is persisted locally
- when there is no stored preference, the app falls back to browser language detection

## 📏 Conventions

- keep translation keys stable and descriptive
- group related keys under section objects when the UI is section-based
- prefer parallel structure between `es.json` and `en.json`
- avoid hardcoding user-facing strings directly in templates when they should be translated

Examples of current grouped areas:

- `brand.*`
- `introduction_section.*`
- `curriculum_page.*`
- `personal_projects_page.*`

## 🔄 Updating translations

When adding a new feature:

1. add the key in `en.json`
2. add the matching key in `es.json`
3. use the key through the `translate` pipe or service
4. verify both languages visually in the UI

## 📝 Notes

- this project uses `ngx-translate`, not Angular generated i18n extraction
- the portfolio content is intentionally bilingual from the UI layer upward
